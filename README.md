# GigaChat-Shell

> Консольный ИИ-помощник на базе GigaChat API для Linux, macOS и Windows.

В репозитории представлены две реализации утилиты `gpt`:
- Bash-скрипт для Linux и macOS.
- Модуль PowerShell 7 для Windows.

## Особенности реализации

- **Минимум зависимостей.** Bash-реализация использует `curl` для HTTP-запросов и `jq` для обработки JSON. Версия для Windows реализована на PowerShell 7 без дополнительных модулей.
- **Без промежуточных языков и сред выполнения.** Скрипты используют штатные средства командной оболочки и не требуют установки Python, Node.js или других дополнительных сред.
- **Единый интерфейс.** В Linux, macOS и Windows утилита вызывается командой `gpt` и поддерживает одинаковый набор флагов.
- **Интеграция с командной строкой.** Запросы можно формировать с помощью параметров и передавать данные через стандартный поток ввода (`stdin`), в том числе из файлов и других команд.
- **Ответ по мере генерации.** Bash-версия читает поток SSE: текст появляется в терминале сразу, а не после полной генерации.
- **Память диалога.** Флаг `-m` продолжает предыдущий диалог, передавая модели последние 10 пар вопрос-ответ. В bash история привязана к текущей сессии оболочки и удаляется сама.
- **Минималистичная архитектура.** Реализация ориентирована на личное использование и решение повседневных задач из консоли. Развитие дополнительных функций и создание универсального фреймворка не входят в задачи проекта.

## Сравнение реализаций

| Возможность | Bash | PowerShell 7 |
| --- | --- | --- |
| Запрос аргументом | да | да |
| Запрос через `stdin` | да | да |
| `stdin` вместе с аргументом | да | нет |
| Кастомный системный промпт `-s` | да | да |
| Ответ печатается по мере генерации | да | нет |
| Память диалога `-m` | да, в рамках сессии оболочки | да, в памяти сессии |
| Кеш OAuth-токена на диске | да | да |
| Код возврата при ошибке | 1 (запрос) / 2 (использование) | не возвращается |

## Подготовка

### 1. Получение API-ключа

1. Авторизуйтесь в [GigaChat API](https://developers.sber.ru/studio/login) через Сбер ID.
2. Создайте проект и выберите инструмент «GigaChat API».
3. В настройках проекта получите Authorization Key и сохраните его. Ключ показывается только один раз.
4. Для физических лиц используйте scope `GIGACHAT_API_PERS` (он зашит в обеих реализациях).

Подробная инструкция: [Быстрый старт GigaChat API](https://developers.sber.ru/docs/ru/gigachat/individuals-quickstart).

### 2. Установка сертификатов

Для работы с GigaChat API установите [сертификаты НУЦ Минцифры](https://developers.sber.ru/docs/ru/gigachat/certificates).

Следуйте инструкциям для вашей операционной системы. Не отключайте проверку TLS-сертификатов для обхода ошибок соединения.

### 3. Установка зависимостей

- **Linux и macOS:** `curl` и `jq`.
- **Windows:** PowerShell 7. Внешние зависимости для работы модуля не требуются.

## Установка и запуск

### Linux и macOS

```bash
export GIGACHAT_CREDENTIALS='Ваш_ключ'

sudo cp bash/gpt.sh /usr/local/bin/gpt
sudo chmod +x /usr/local/bin/gpt
```

Переменная окружения должна быть задана в той оболочке, из которой запускается утилита. Для постоянного использования её можно добавить в конфигурацию оболочки, например в `~/.bashrc` или `~/.zshrc`:

```bash
export GIGACHAT_CREDENTIALS='Ваш_ключ'
```

Удаление: `sudo rm /usr/local/bin/gpt` и, при необходимости, `rm -rf ~/.local/gigachat_*`.

### Windows, PowerShell 7

```powershell
$env:GIGACHAT_CREDENTIALS = 'Ваш_ключ'

$modulePath = "$HOME\Documents\PowerShell\Modules\GigaChat"
New-Item -ItemType Directory -Force -Path $modulePath
Copy-Item .\GigaChat.psd1 $modulePath
Copy-Item .\GigaChat.psm1 $modulePath
```

После установки перезапусти PowerShell. Если каталог Documents перенаправлен в OneDrive или изменён настройками системы, путь установки может потребовать корректировки.

Удаление: `Remove-Item -Recurse "$HOME\Documents\PowerShell\Modules\GigaChat"`.

## Использование

Флаги одинаковы в обеих реализациях:

- `-s "промпт"` — кастомный системный промпт вместо стандартного.
- `-m` — продолжить предыдущий диалог. Без `-m` история начинается заново.
- `-h` — справка.
- `--` — конец флагов; нужен, если запрос начинается с дефиса.

Ответ печатается по мере генерации: первые слова появляются через 0,3–1,5 с, остальное дописывается без задержки на полный ответ.

### Linux и macOS

```bash
# Обычный запрос
gpt "Объясни разницу между TCP и UDP"

# Запрос с кастомным промптом
gpt -s "Ты опытный Linux-администратор. Отвечай кратко, предлагай конкретные команды." "Как найти процесс, занимающий порт 8080?"

# Данные из stdin: если аргумент не указан, весь stdin становится запросом
cat /etc/nginx/nginx.conf | gpt -s "Проверь конфигурацию на типичные ошибки и потенциальные проблемы"

# Данные из stdin вместе с аргументом: stdin добавляется к запросу отдельным блоком
journalctl -p err -n 50 | gpt "Проанализируй ошибки и предложи варианты диагностики"

{ ip addr; ip route; } | gpt "Проанализируй сетевую конфигурацию и укажи возможные проблемы"

# Память диалога
gpt "Что делает команда ss?"
gpt -m "А как показать только слушающие сокеты?"

# Запрос, начинающийся с дефиса
gpt -- "-rf опасен при удалении?"
```

### Windows

> Модуль хранит до 10 пар вопрос-ответ в рамках текущей сессии PowerShell; история не сохраняется между сессиями. Bash-версия ведёт себя так же: диалог живёт, пока открыта оболочка.

```powershell
# Обычный запрос
gpt "Объясни разницу между TCP и UDP"

# Запрос с кастомным промптом
gpt -s "Ты опытный Windows администратор. Отвечай кратко, предлагай конкретные команды." "Как найти процесс, занимающий порт 8080?"

# Анализ файла: содержимое передаётся через конвейер (pipeline),
# чтобы не упираться в лимит длины командной строки
Get-Content "$HOME\Documents\PowerShell\Modules\GigaChat\GigaChat.psm1" -Raw |
    gpt "Проанализируй код модуля на ошибки"

# Если хотите разделить роль и задачу
Get-Content "$HOME\Documents\PowerShell\Modules\GigaChat\GigaChat.psm1" -Raw |
    gpt -s "Ты опытный ревьюер PowerShell-кода" "Проанализируй модуль на ошибки"

# Анализ файла с GitHub
Invoke-RestMethod -Uri 'https://raw.githubusercontent.com/rz6agx/gigachat-shell/refs/heads/main/powershell/GigaChat.psm1' | gpt "Проанализируй код модуля на ошибки"

# Начало диалога (без -m история сбрасывается)
gpt "Что делает Get-ChildItem?"

# Продолжение диалога: -m сохраняет предыдущий контекст
gpt -m "Как вывести только файлы?"
gpt -m "А как отсортировать их по размеру?"
```

## Настройки и файлы состояния

Bash-версия читает переменные окружения:

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `GIGACHAT_CREDENTIALS` | — | ключ авторизации, обязателен |
| `GIGACHAT_MODEL` | `GigaChat-2-Pro` | модель |
| `GIGACHAT_TIMEOUT` | `120` | таймаут запроса, секунды |
| `GIGACHAT_BASE_URL` | `https://api.giga.chat` | адрес API |

Пример: `GIGACHAT_MODEL=GigaChat-2-Pro gpt "Коротко: что такое NAT?"`

Создаваемые файлы (права `600`):

- `~/.local/gigachat_token` — OAuth-токен и срок его действия. Удалите файл, чтобы принудительно получить новый.
- `~/.local/gigachat_history_<pid оболочки>` — история для `-m`. Файл относится к конкретной оболочке и удаляется автоматически, когда она завершается.

PowerShell-версия кеширует токен в `%LOCALAPPDATA%\gpt\gigachat_token`, историю держит только в памяти сессии.

При обновлении с предыдущей версии удалите старый `~/.local/gigachat_history.json` и файлы `gigachat_history_*` из `$TMPDIR` — новая версия их не использует.

## Коды возврата (bash)

| Код | Значение |
| --- | --- |
| 0 | успешный ответ |
| 1 | нет ключа, ошибка сети, ошибка API, некорректный ответ |
| 2 | ошибка использования: неверный флаг, `-s` без значения, пустой запрос |
| 130 | прервано по Ctrl+C |

PowerShell-версия печатает сообщение об ошибке в stderr, но код возврата не меняет — учитывайте это в скриптах.

## Диагностика

- **`Ошибка получения токена (HTTP 400/401)`** — неверный `GIGACHAT_CREDENTIALS`. Для физических лиц ключ должен быть выпущен для scope `GIGACHAT_API_PERS`.
- **HTTP 403 на запрос к API** — у ключа нет доступа к выбранной модели или исчерпан лимит.
- **`SSL certificate problem`, `self-signed certificate`** — не установлены сертификаты НУЦ Минцифры. Не отключайте проверку TLS, установите сертификаты по инструкции выше.
- **`jq: command not found`** — установите `jq` (`apt install jq`, `brew install jq`).
- **`Токен отклонён сервером`** — токен отозван; утилита получает новый автоматически, повторного вмешательства не требуется.
- **`-m` не помнит предыдущий запрос** — история привязана к оболочке. Вызов в пайпе (`gpt "..." | bat`) и вызов из другого терминала считаются отдельными сессиями.
- **Ответ приходит, но не учитывает переданные данные** — в PowerShell-версии `stdin` используется только без аргументов; передавайте данные аргументом или одним `stdin`.
